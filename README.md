# Эмулятор оболочки ОС - вариант 30, этап 5

Минимальный GUI-прототип на Python и `tkinter`. Большое поле показывает
историю диалога и прокручивается, нижнее поле принимает команду, а кнопка `>`
и клавиша Enter запускают ее.

## Требования

- Python 3.10 или новее;
- стандартный модуль `tkinter`.

В Windows `tkinter` обычно входит в стандартную установку Python. На Linux
может понадобиться пакет `python3-tk`.

## Запуск

Windows:

```text
run.bat
```

Любая система с Python:

```text
python -m src.main
```

Linux/macOS:

```text
./run.sh
```

## Параметры запуска

```text
python -m src.main --vfs path/to/vfs.xml --script scripts/startup.txt
```

- `--vfs` - путь к физическому расположению VFS;
- `--script` - путь к стартовому скрипту команд эмулятора.

При запуске оба параметра выводятся в журнале приложения. Стартовый скрипт
выполняется последовательно: каждая строка показывается как ввод и вывод,
ошибочные строки сообщаются и пропускаются.

После ошибки выполнение продолжается. В конце выводится
`Где то в вашем скрипте ошибка`, после чего можно вводить команды вручную.
Если в скрипте уже была ошибка, последующие `exit` не закрывают приложение
и не прерывают оставшиеся команды. В интерактивном вводе `exit` работает
как обычно.

Примеры запуска на Windows: `scripts\\stage2_basic.bat` и
`scripts\\stage2_errors.bat`. Для Linux/macOS предусмотрены одноименные
скрипты с расширением `.sh`.

## Проверка и ограничения репозитория

Проект использует только стандартную библиотеку Python и не требует отдельной
сборки. При необходимости исходный код можно проверить компиляцией в байт-код:

```text
python -m compileall -q src tests
```

Созданные каталоги `__pycache__` исключены из репозитория через `.gitignore`.

В заголовке окна отображается имя загруженной VFS. XML-файл подключается
в память и не изменяется во время работы приложения.

## Поддерживаемые на этапе 5 команды

- `ls [-lha] [путь]` - список узлов текущего или указанного каталога;
- `cd [путь]` - переход в каталог, включая `.` и `..`;
- `clear` - очистка поля вывода;
- `uptime` - время работы эмулятора;
- `rm [-r|-R] путь` - удаление узла только из памяти VFS;
- `chmod режим путь` - изменение UNIX-подобных прав в памяти VFS;
- `exit` - закрывает приложение.

Флаги `ls` можно объединять в любом порядке (`-lha`, `-hal`, `-lh`, `-la`)
или задавать отдельно (`-l -h -a`), до или после пути. `-l` выводит права,
размер и имя; `-h` вместе с `-l` показывает размеры в K, M, G (по 1024);
`-a` добавляет скрытые имена, `.` и `..`. Без `-a` скрытые имена не выводятся.
Для имени, начинающегося с дефиса, используйте `ls -- имя`.

В путях `cd` и `ls` точка означает текущий каталог, две точки — родительский.
Из корня VFS работают, например, `cd ./home`, `cd home/.`,
`cd home/..`, `cd home/../home`; затем `cd ..` возвращает в корень.
Компоненты пути разделяются `/`: `home..` — обычное имя, а `home/..` —
переход через `home` в родительский каталог.

Ошибки разбора, неизвестные команды, отсутствующие пути и лишние аргументы
отображаются в истории диалога. Скрипты сценариев этапов 4 и 5 находятся
в `scripts/stage4_basic_demo.txt` и `scripts/stage5_additional_demo.txt`.
Для запуска используйте соответствующие `.bat` или `.sh`-файлы.

Для удаления каталога нужен ключ `-r` или `-R`; корень VFS удалить нельзя.
Команды `rm` и `chmod` изменяют только дерево в памяти и не перезаписывают
XML-источник.

## Виртуальная файловая система

На этапах 3-5 VFS загружается из XML в память. Исходный XML-файл не
распаковывается и не изменяется. Текстовые файлы хранятся в UTF-8, двоичные
файлы задаются атрибутом `encoding="base64"`.

В репозитории есть три варианта VFS:

- `data/vfs/minimal.xml` - минимальное дерево;
- `data/vfs/several-files.xml` - несколько файлов и base64-файл;
- `data/vfs/nested-three-levels.xml` - вложенность более трех уровней.

Для демонстрации используйте `scripts/stage3_minimal.bat`,
`scripts/stage3_several_files.bat` или `scripts/stage3_nested.bat`. Скрипты
`.sh` выполняют те же сценарии в Linux/macOS.

Парсер поддерживает раскрытие переменных окружения реальной ОС в формах
`$NAME` и `${NAME}`. Если в Windows отсутствует `HOME`, для `$HOME`
используется значение `USERPROFILE`. Клавиши Up/Down возвращают команды из
истории сеанса.

## Сценарий демонстрации

Введите команды по очереди:

```text
ls
ls -la documents
cd $HOME
cd "$HOME/My Documents"
cd $USERPROFILE
unknown
exit now
"незакрытая строка
exit
```

Ожидаемый результат:

- `ls` и `cd` печатают имя команды и аргументы;
- переменная `$HOME` раскрывается из окружения ОС;
- неизвестная команда, лишние аргументы для `exit` и ошибка кавычек
  выводятся сообщениями об ошибке;
- `exit` закрывает окно.

Пример интерактивного диалога; имя пользователя, хоста и домашнего каталога
зависят от реальной ОС:

```text
user@host:~$ ls -la documents
ls: заглушка; аргументы: -la documents
user@host:~$ cd $HOME
cd: заглушка; аргументы: /home/user
user@host:~$ unknown
Ошибка: неизвестная команда 'unknown'.
user@host:~$ exit now
Ошибка: команда exit не принимает аргументы.
user@host:~$ exit
```

## Проверка

Запуск модульных тестов:

```text
python -m unittest discover -s tests -v
```

Проверка стиля выполняется для каждого Python-файла: длина строки не более
80 символов, имена соответствуют PEP 8, функции не перегружены аргументами
или логикой. В репозиторий не включаются кэш Python, настройки редакторов,
архивы, бинарные файлы и артефакты сборки.
